# comp211checkoff

This analysis explores why C generally outperforms Python, focusing on reference counting, the memory management strategy used by CPython. In reference counting, each object tracks how many references point to it (ob_refcnt). The count increases with new references and decreases when references are removed; the object is freed when the count reaches zero. Python handles this automatically, while C requires manual management, increasing the risk of memory leaks, use-after-free errors, and unsafe references. Python’s slower performance is due to three main factors: it interprets code one bytecode instruction at a time instead of compiling to machine code, checks types before every operation, and treats every value as a full object whose reference count must be updated. As a result, simple loops can run 10 to 100 times slower in Python than in C. However, built-in functions like sum() and libraries such as NumPy are implemented in C, so Python is slower per step, not necessarily per task.
